1 问题描述

​ 在中标麒麟桌面/服务器操作系统上，当systemd-journald持续产生大量日志时，由于rsyslog需要进行读取，并写入/var/log/message日志文件，会造成下面两个问题：

  1. rsyslog进程占用CPU过高；
  2. /var/log/message日志文件的规模增大过快。

2 相关名词

2.1 systemd-journald​

中标麒麟桌面/服务器操作系统中，systemd-journald是systemd的日志记录系统，收集来自内核、启动过程早期阶段、标准输出、系统日志、守护进程启动和运行期间错误的信息。

systemd-journald在收集日志的同时进行转发日志，接收日志转发的方法有两种：

  1. 通过套接字文件监听；
  2. 作为客户端运行。

2.2 rsyslog​

中标麒麟桌面/服务器操作系统中，rsyslog是systemd-journald的日志接收进程。rsyslog采用的是作为客户端运行的方式接收systemd-journald转发的日志，此方法读取日志不能实时读取日志消息，但是可以读取先前保存的日志消息（例如在系统启动完成之后读取系统启动早期的日志消息）。

2.3 logrotate​

logrotate是一个日志文件管理工具。用来把旧文件轮转、压缩、删除，并且创建新的日志文件。可以根据日志文件的大小、天数等来转储，便于对日志文件管理。

3 原理分析

​ 中标麒麟桌面/服务器操作系统中，在rsyslog占用高时，查看其线程，可以发现主要是in:imjournal线程占用高，in:imjournal的功能是读取journal的日志，因此，rsyslog进程占用高的主要原因是：在读取journal时消耗大量CPU资源。

​ 由于rsyslog不是实时读取journal日志消息，而是读取先前存储的日志，每当有新消息时都要去重新读取整个日志文件，所以当journal越大时，rsyslog消耗CPU越高。另外，根据系统的默认设置，systemd-journald收集的日志是保存在磁盘中，频繁大量的读写也是导致CPU消耗过高的原因。

4 优化方案

4.1 解决rsyslog占用CPU过高的优化方案​

4.1.1systemd-journald日志存储设置原理介绍​

优化的思路是对systemd-journald日志的存储方式进行优化配置。systemd-journald日志的配置文件为/etc/systemd/journald.conf，具体内容如下：

其中，

（1） Storage：表示journal日志的保存方式，可设置的参数有：

l "volatile"：表示仅保存在内存中，即仅保存在 /run/log/journal目录下；

l "persistent"：表示优先保存在磁盘上，即优先保存在 /var/log/journal目录下；

l "auto"（默认值）与"persistent"类似，但不自动创建/var/log/journal目录，是根据该目录的存在与否决定日志的保存位置，如果存在保存在/var/log/journal目录下，如果不存在保存在 /var/log/journal目录下；

l "none" 表示不保存任何日志。

在中标麒麟桌面/服务器操作系统和银河麒麟桌面操作系统上，使用的是默认值”auto”，由于系统中默认没有创建 /var/log/journal，因此，日志保存在 /run/log/journal目录下。只有通过手动创建 /var/log/journal目录后，在系统下次启动或者重启systemd-journald服务后日志则保存才会在/var/log/journal目录下。

​ （2）SystemMaxUse：限制全部日志文件加在一起最多可以占用多少磁盘空间，也就是 /var/log/journal的使用量。SystemMaxUse的默认值是10%的磁盘空间与4G空间两者中的较小者。

​ （3）RuntimeMaxUse：限制全部日志文件加在一起最多可以占用多少内存空间，也就是 /run/log/journal的使用量。“RuntimeMaxUse”的默认值是10%的内存空间与4G空间两者中的较小者。

​ （4）SystemMaxFileSize：限制单个日志文件的最大体积，到达此限制后将会删除一个老日志文件，增加一个新日志文件。默认值是 “SystemMaxUse”的1/8。

​ （5）RuntimeMaxFileSize：限制单个日志文件的最大体积，到达此限制后将删除一个老日志文件，增加一个新日志文件。默认值是“RuntimeMaxUse”值的1/8。

4.1.2 解决rsyslog占用CPU高的优化方案​

由于日志保存在内存比保存在磁盘时的访问速度快，所以当journal日志保存在内存时，rsyslog读取日志时占用的CPU，要比保存磁盘上更低。因此，将journal日志设置为仅保存在内存中。并限制所有日志文件和每个日志文件的占用空间。对/etc/systemd/journald.conf配置文件的修改如下：

l Storage=volatile；

l RuntimeMaxUse=120M；

l RuntimeMaxFileSize=8M。

4.1.3方案评价​

1、解决了rsyslog占用CPU过高的问题；

2、理论上来说，将日志保存在内存中，由于设置的存储空间有限，可能会存在日志产生的速度大于rsyslog读取的速度，导致部分早期日志未被读取就被删除。因此，为了验证该方案的实际效果，进行模拟实验，验证systemd-journald在快速产生日志的情况，是否会导致日志丢失的情况。

验证情况如下：

1）systemd-journald每秒产生6千行日志的情况下，没有丢失。

2）systemd-journald每秒产生7千行日志的情况下，rsyslog读取速度略小于systemd-journald产生日志速度，当打印时间持续超过10小时，会出现丢失。

4.2解决日志文件过大的优化方案​

4.2.1logrotate日志管理工具介绍​

logrotate的配置文件为/etc/logrotate.conf，该配置定义了定义了如何处理日志，配置说明如下：

l create：日志切割后，创建一个新的空文件（默认）

l nocreate：日志切割后，不建立新的日志文件

l dateext：切割后的日志以当期日期为格式结尾（默认）

l dateformat .%s：定义文件切割后的文件名，必须配合dateext使用，只支持 %Y %m %d %s 四个参数

l daily：指定切割周期为每天

l weekly：指定切割周期为每周（默认）

l monthly：指定切割周期为每月

l rotate count：保留轮转后日志文件个数（count默认为4）

l size size：当日志文件到达指定的大小时才切割

4.2.2 解决日志文件过大的优化方案​

现有两套方案：

​ （1）通过logrotate日志轮转，限制/var/log/message单个文件大小，当日志达到一定大小时，进行日志切割，现建议设置大小为1M，即在/etc/logrotate.conf中添加一行size 1M。

​ （2）增加日志过滤机制，对于重复打印的调试信息(1秒大于等于1行)，弹框提示用户关闭应用软件调试信息，并屏蔽上述调试信息(该方案还需讨论具体实施计划)。
